# Q1

## 题干
什么是 MySQL 的覆盖索引（Covering Index）？它与普通索引回表查询相比，优势体现在哪里？**

## 开卷
覆盖索引定义及与回表查询的性能对比
- 定义：查询所需全部数据（SELECT、WHERE、ORDER BY等）均可从索引树直接获取，无需回表访问聚簇索引
- 判定方式：执行计划Extra字段显示'Using index'
- 核心优势-减少IO：避免回表产生的随机I/O，显著降低延迟并提升吞吐量
- 核心优势-缓存友好：索引体积通常小于数据行，提高Buffer Pool缓存命中率
- 额外收益：索引天然有序，若满足ORDER BY则可避免filesort排序开销
- 设计注意：索引宽度不宜过宽（防止索引膨胀），适合高并发低延迟场景，不适合宽表全列查询

## 作答
覆盖索引是查询要用的列都能从二级索引上拿到，不用回表去聚簇索引读整行。执行计划 Extra 里常见 Using index。好处是少一次随机 IO，索引更小也更吃缓存；如果排序字段也在索引里，还能避开 filesort。代价是索引不能太宽，否则膨胀，宽表全列查询覆盖不了。
