## Context

现有 `watch-coach-turn` 在追加下一张卡前等待简报、知识链和宿主空闲，导致 Jev 已经决定路由后仍有一段不可见等待。产品要求卡片跟随面试官节奏出现，面板不能成为第二个聊天表面；所有教练内容仍只在右侧面板展示。

## Goals / Non-Goals

**Goals:**

- 将“题干和编号可见”与“参考资料完整”拆成两个可持久化阶段。
- 让预览卡片先进入 remote snapshot、卡片流和工作区，再异步补齐参考内容。
- 复用现有会话级 single-flight、版本守卫、取消和增量落盘机制。
- 保持现有卡片编号、Jev 路由、历史卡切换和 DSH 宿主对话边界。

**Non-Goals:**

- 不在面板内新增聊天输入框、气泡或独立模型。
- 不让 Jev 生成题干、参考要点、对照或评分。
- 不改变 `miss`、`wide_gap` 的原卡引导规则。
- 不承诺未经实测的流式远程 API；本 change 使用已有阶段快照和异步补齐。

## Decisions

1. **新增 `preview_ready` 阶段。**
   在 `answer_received` 之后、`coverage_ready`/`comparison_ready`/`brief_ready` 之前加入 `preview_ready`，并同步 shared、Host 类型和 Client 解码。这样前端可以区分“卡片已出现但参考内容未完成”和“待答/评分中的旧状态”。

2. **预览阶段使用本地摘要。**
   题干摘要从已返回题干做去 Markdown、首句和长度裁剪，不调用模型。`questionBrief` 在预览阶段是可读的临时摘要，`keyPoints` 为空并由前端按阶段显示生成中。

3. **拆分开卡与补齐。**
   后端先计算关系和编号，创建 `preview_ready` 卡片并提交；随后启动一次可取消的 enrich 任务调用 `briefQuestion`，再安装知识链并把结果合并回相同卡片。enrich 失败只更新错误阶段，不删除预览卡。

4. **使用卡片编号和版本双重守卫。**
   enrich 写回前校验 session 仍有效、卡片仍存在、版本未被新作答推进且任务未取消。远端合并继续使用阶段排序，避免旧补齐结果覆盖更新后的卡片。

5. **面板把空要点解释为阶段状态。**
   `preview_ready` 或空 `keyPoints` 时显示参考内容生成中；失败阶段显示错误；题干和编号在两种状态都可查看。生成槽只用于尚未得到题干的等待，不覆盖已发布的预览卡。

## Risks / Trade-offs

- [Risk] 预览摘要不是模型生成的完整题意，可能只包含题干首句 → 使用完整题干作为详情主内容，并在参考内容完成后替换摘要，不把临时摘要当作标准答案。
- [Risk] 预览先落盘、补齐后失败会留下不完整卡片 → 明确阶段和错误字段，恢复时保留卡片并允许后续手动刷新补齐。
- [Risk] 宿主 idle 尚未到达时知识链不能安装 → 不阻塞卡片可见，补齐任务在 idle 后重试一次，失败保持可见错误。
- [Risk] 旧客户端不认识新阶段 → 新阶段只在本 change 对应的 Host/Client 组合包中发布，并为未知阶段保留失败降级文案。

## Migration Plan

先更新 shared 阶段契约和前后端类型，再改后端拆分开卡与补齐，随后更新面板和单测。构建并安装组合包后，在真实 DSH Desktop 中验证 Jev 路由后的预览卡、异步参考内容、失败保留、结束取消和工作区恢复。若发现问题，可回滚组合包；已有 `preview_ready` 文件按阶段读取，旧版本无法识别时显示通用生成状态，不删除已有卡片。
