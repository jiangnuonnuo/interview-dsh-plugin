## Why

入口面板已经能选主题/难度并校验「开始」，但点开始后仍停在「待开考」，当前对话没有面试官、面板也没有本题要点。第一期主链路的下一步就是：开始后立刻套上面试官、建立教练会话、出现第一问，且面板同步出标准答要点。

## What Changes

- **BREAKING**（相对已归档的 `interview-entry`）：合法的「开始模拟面试」不再只记配置。成功后必须注入会话 A（面试官）、建立会话 B（教练）、在当前 DSH 对话产出第一问，面板切到进行中并展示本题标准答要点。
- 新增双会话能力：两条会话都使用当前这条 DSH 对话已配置的 AI；不读开始前历史；教练输出永不进气泡。
- 第一问由模型按主题与难度动态生成，不靠预写死题库。
- 面板在第一问出现时即可看题干摘要与标准答要点；评分区可以占位，本 change 不要求处理用户作答后的追问或评分更新。
- 查不到 Host 注入/隔离 API 时适配层标 `TODO` 并在面板给出可见失败，禁止自建聊天绕过。
- 本 change 不做：提示/跳过/停止卸角、用户作答后的追问循环、落盘 `study/`、项目深挖/混合模式。

## Capabilities

### New Capabilities

- `interview-session`: 开始后的双会话、面试官注入、第一问出现在当前对话、教练面板展示本题要点；桌面端实机验收为交付门闩。

### Modified Capabilities

- `interview-entry`: 「开始模拟面试」从「只校验并待开考」改为启动 `interview-session`；待开考不再是成功开始的终态。

## Impact

- `shared/`：开始结果与进行中面板状态的类型（会话阶段、当前题干、要点；不含前端评分判定）。
- `backend/`：Host 适配层查官方 Agent/会话注入 API；服务层组装八股专项面试官提示词并启动教练会话；不得把密钥或评分逻辑放到前端。
- `frontend/`：入口面板成功开始后切到进行中视图（同一 overlay/右栏，无聊天页）；展示主题、题干摘要、标准答要点、评分占位。
- `interviewer-role-prompt.md`：八股专项模板化后注入会话 A，不改 DSH 核心。
- 依赖：仅已随 Desktop 提供的 Host/Client SDK；无新密钥、无自建模型配置。
