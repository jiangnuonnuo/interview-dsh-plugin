## Context

现有实现以 `watchCoachTurn` 为单次长轮询入口。它在一个请求内读取宿主事件、识别人类作答、并行启动 Jev 与默认模型补全，之后按阶段写回甲板并重写工作区文件。前端以 Promise 方式反复调用 remote；当前没有会话级 single-flight，也没有可表达“定档已到、对照仍在生成”的共享状态。

实现必须继续遵守 DSH 插件边界：面试官仍由宿主对话生成，教练结果只进入右侧面板；Client 只能通过 `shared` 契约和官方 remote；未确认的官方事件流 API 不得猜测；Host 文件写入仍走 `ctx.fs`。

## Goals / Non-Goals

**Goals:**

- 让同一会话同一作答只有一个评估任务，并让后台看守与手动刷新共享它。
- 让定档、对照/五维和下一题 brief 可以分别完成、分别发布和分别恢复。
- 让面板在结果生成期间保持当前卡、历史卡、详情和生成槽可用。
- 让旧卡片档案可读取，阶段性保存幂等，过期任务不能覆盖新版本。
- 在不新增宿主聊天表面的前提下提供阶段级“流式”体验，并保留现有 Promise remote 的兼容性。

**Non-Goals:**

- 不把教练文本或卡片结果写进考场气泡。
- 不改变覆盖五档语义、reask 上限、卡片编号和默认模型评分规则。
- 不实现未经确认的 token 级 DSH remote 流；`llm.stream` 仍只作为后端补全的输入源。
- 不引入队列服务、数据库或新的运行时依赖。
- 不把 Jev 改造成评分、开卷要点或知识链生成器。

## Decisions

### 1. 用会话级 single-flight 任务表协调请求

在服务编排层按 `sessionId` 保存短生命周期任务状态。任务键由会话、卡片编号、作答版本指纹组成；任务包含 `generation`、取消控制器、阶段结果、共享 Promise 和订阅者数量。`watchCoachTurn` 与 `force` 请求先查任务表，命中时等待或读取同一任务；只有新作答版本才创建新任务。

选择服务层任务表，是因为并发去重属于用例编排，不应放进 DSH 适配层或 React。任务表只保存进行中的任务和最近完成版本，轮次结束、失败或 TTL 到期即清理；会话重启后以磁盘甲板为真源，不依赖进程内任务表恢复。

替代方案：仅在前端加请求锁。否决，因为多个 Client、远端重试和桌面重载仍会重复调用；仅在 Host 适配层加锁也无法保护领域层的版本写入。

### 2. 用阶段快照表达“流式”结果

在 `shared` 增加可选的阶段状态和版本字段，至少表达：评估中、定档已完成、对照已完成、brief 已完成、失败/取消。每次 remote 返回都携带当前可见 deck 快照和阶段状态；前端按 `generation` 丢弃旧快照，只合并更新字段。

阶段边界如下：

1. 读取作答并建立评估版本，立即把作答写入内存甲板。
2. Jev 命中或对照回退得到合法覆盖结果后，先发布卡片路由；对照 JSON 若尚未完成，原卡保留“对照生成中”。
3. 默认模型完成后写回已覆盖、未覆盖、评语和五维。
4. 新题 brief 完成后才追加下一卡；brief 期间只显示邻卡生成槽。

由于 DSH 当前 remote 契约是 Promise，阶段更新通过短轮询获取，不能假设 Server-Sent Events 或官方订阅 API。后端 `llm.stream` 仍收集结构化 JSON 完整文本，避免把半截 JSON 展示给用户。

替代方案：把每个 token 直接透传到面板。否决，因为当前没有确认的官方 remote 事件契约，半截 JSON 也无法安全地用于卡片字段；先做阶段流能获得主要体感收益且不破坏宿主边界。

### 3. 用版本校验保护异步写入

每次作答递增 `answerVersion`，每个阶段带 `generation` 和 `stage`。写入前检查任务仍是会话当前任务、版本仍等于卡片当前版本且会话未结束；不满足时丢弃结果。卡片更新采用字段合并：定档阶段只能写路由和生成状态，对照阶段只能写对照/评分，brief 阶段只能追加新卡。

这样可以处理“补充作答先到、上一轮评分后到”和“结束本轮后旧请求返回”两类竞态，不需要回滚新作答。

### 4. 把 Jev 连接探测状态绑定到配置指纹

成功探测结果在配置仓储或会话启动上下文中记录配置指纹与时间；开始面试只在指纹未变化且仍在有效窗口时复用。密钥变化、启用状态变化、探测过期或新轮次策略要求重新确认时，才调用探针。定档请求仍只由 coverage port 发起，密钥不进入 shared 请求体或面板响应。

替代方案：永久缓存探测成功。否决，网络、权限和密钥撤销会使永久结果不可靠。

### 5. 局部、幂等落盘

扩展 `WorkspaceArchive` 的写入能力，使阶段提交携带当前 deck 版本和发生变化的卡片集合。Host 适配层先写对应 `cards/<id>.md` 与 session 索引，再以同一版本标记完成；重复提交相同版本不追加内容。无法支持局部写入时保留整副牌回退实现，但服务层仍必须保证版本和幂等。

选择接口扩展而不是在 services 直接访问文件，是为了维持 `services → data → infra` 依赖方向。session.json 继续保存完整可恢复甲板，card markdown 用于用户查看。

### 6. 前端只消费阶段状态，不作业务判定

`EntryPanel` 只负责启动 single-flight、应用新快照和取消旧订阅；`InProgressPanel` 根据后端阶段状态渲染对照/评分占位和下一卡槽。卡片路由、五档和分数仍由后端生成，前端不推断是否开子卡或换题。

后台看守与手动刷新共用同一订阅，不再各自启动完整评估。组件卸载或结束本轮时取消订阅，并清理本地重试定时器。

### 7. 新题等待采用短稳定窗口

适配层发现不同于基线的题干后，先等待宿主进入 idle 或短稳定窗口；稳定窗口到期仍未 idle 时只发布题干已发现状态，brief 任务异步继续。不得用剩余的整段 20 秒看守超时等待 `whenIdle`。题干抽取、route-plan 错误过滤和现有自然语言边界保持不变。

## Risks / Trade-offs

- [风险] 阶段快照增加 remote 请求次数和状态字段。→ 只在阶段变化或短轮询窗口到期时返回；同一版本命中缓存直接返回，不再次调用模型。
- [风险] 进程崩溃会丢失进行中的任务。→ 任务表只作并发协调，磁盘 session.json 仍是恢复真源；恢复后允许重新评估未完成阶段。
- [风险] 局部落盘失败造成面板与文件短暂不一致。→ 保存版本号和可见持久化错误；下次看守按当前版本重试，禁止宣称已保存。
- [风险] Jev 先于对照完成时，卡片路由与可见评语暂时不同步。→ 面板明确显示阶段状态，定档结果只控制路由，最终对照仍写回原卡；两边都失败时沿用现有错误码。
- [风险] 宿主事件快照在高频轮询下开销增加。→ 每个评估版本缓存事件读取与题干指纹，只有事件长度或最新消息指纹变化时重新解析。
- [风险] single-flight TTL 过短会使慢任务被第二次启动。→ TTL 只清理已完成或明确失败的任务；运行中任务由取消信号和会话结束显式清理。

## Migration Plan

1. 先扩展 shared 阶段状态与版本字段，保持旧字段可选，旧 session.json 可按 pending/scored 兼容读取。
2. 再实现后端任务协调、阶段发布、版本校验和局部落盘，默认保留现有对照回退路径。
3. 接入前端阶段快照和取消逻辑，确保没有阶段字段时仍按现有卡片渲染。
4. 通过仓库单测、打包检查和真实 DSH Desktop 场景验证后再启用新的阶段体验。
5. 回滚时关闭阶段任务入口，继续使用原有一次性 `watchCoachTurn`；shared 新字段保持可选，不影响旧档案读取。
