## Context

见 `proposal.md` 的 Why。现状代码：对照补全只返回已覆盖、未覆盖、评语和五维；下一题 brief 另填 `matchedMove`，`relationForNextCard` 用它把追问一律建成 `Qn.m`。`clipChain` 在同一知识点达到 2/3/4 问后把系统段改成只许换知识点。`QuestionCard.answer` 是单段字符串。考生一发送，宿主面试官已经开始生成，看守只能在回合结束后读对照。

## Goals / Non-Goals

**Goals:**

- 对照补全增加一个代码可执行的覆盖结果。代码只按这个结果留在原卡、开子卡或开下一正式问。
- 原卡作答按轮保存，引导后的对照覆盖旧对照。
- 系统段按难度写引导尺度，不再用题数上限换题。

**Non-Goals:**

- 不新增会说话的模型，不等对照完成再 `session.prompt`。
- 不在面板展示五种结果，不加提示或跳过按钮。
- 不重做卡片流的滑动。不改开场句和「结束面试」。

## Decisions

### 1. 覆盖结果跟对照同一次返回

对照 JSON 增加 `coverage`，取值只允许 `miss`、`wide_gap`、`deepen`、`reask`、`next`。已覆盖和未覆盖清单仍然给人看。代码把 `miss` 与 `wide_gap` 留在原卡，`deepen` 与 `reask` 开 `Qn.m`，`next` 开下一个 `Qn`。解析不到 `coverage` 时面板给出可见错误，作答留在原卡，不新开卡。

备选：用未覆盖条数推断缺口大小。否决，同义说法和缺口大不大都不是条数问题。

备选：继续用 brief 的 `matchedMove`。否决，那是下一题材料里的猜测，和对照是否对上考察意图不是同一次判断。

### 2. 作答按轮存在原卡上

卡片增加 `answerTurns`。每一轮考生发言追加一条。`answer` 保留为各轮按序拼成的全文，给现有读取和落盘使用。引导重算对照时，评分用户材料用全文，不用单独最后一轮。详情的作答折叠按轮展示。`cards/<id>.md` 写出各轮，不另建引导卡文件。旧档只有 `answer` 时，读成一轮。

备选：只在 `answer` 里插分隔符。否决，面板和测试无法稳定分出轮次。

### 3. 引导次数记在卡上

卡片增加 `guideCount`。`miss` 或 `wide_gap` 且 `guideCount` 小于 2 时，次数加一，更新对照，不调用追加新卡。次数已经到 2 且结果仍是 `miss` 或 `wide_gap` 时，这张卡定稿，不再引导。此后若面试官把同一题拆开再问，新卡是 `Qn.m`；只有对照为 `next`，或这一问明确换了知识点，才开下一个 `Qn`。`deepen`、`reask`、`next` 不增加 `guideCount`。

备选：不设上限，一直引导到模型改口。否决，同一题可能停不住，规格已把两轮写成上限。

### 4. 系统段只约束说法，不决定开卡

`renderChainSection` 去掉按题数写死的「必须换知识点」。段内写五种结果各自该说成引导、子问还是换题，并写入本难度的引导尺度：初级可点出步骤，中级只点缺口，高级只标那一刀，且 `next` 必须换前提或换规模。层裁剪仍用现有允许层表。面试官开口早于对照，所以段必须事先挂上。开卡只读 `coverage`。面试官已经问了别的，只要 `coverage` 是 `miss` 或 `wide_gap`，仍然不建卡。

备选：等对照结束后再让面试官说。否决，宿主在考生发送时已经生成，再 `prompt` 会多一条用户气泡。

### 5. 新卡仍走现有 brief

只有 `deepen`、`reask`、`next` 才抽取新的待答问并走现有开卷要点。`deepen` 与 `reask` 的关系固定为追问，`next` 固定为下一知识点。`matchedMove` 只在对照不是这三档时区分是否换了知识点；缺省不是换知识点。

### 6. 知识链缺字段时先重试，再补合法链

开卷 JSON 有要点但没有合法 `pointName`、`layer`、`intent`、`moves` 时，用同一道题再要一次完整链。仍不合法，就用题干摘要、第一条要点和该难度起手层（初级定义，中级与高级原理）补一份链，三档写成引导、拆开子问、换知识点，再走现有层裁剪并挂上系统段。不摘段，不退回人设。这取代「解析失败就退回人设」。系统段接口挂载失败仍返回可见错误。

备选：改人设去补没有系统段时的追问。否决，人设已经要求遵守系统段，缺的是段本身。

## Risks / Trade-offs

- [面试官先问出新题，对照却要求留在原卡] → 气泡里会暂时看到那句，面板不建卡。规格把对照当作开卡依据，接受这一拍不一致。
- [模型不返回 `coverage`] → 可见错误，作答留在原卡，避免按 `matchedMove` 误开子卡。
- [`interview-knowledge-chain` 尚未归档] → 本 change 直接改已经落地的开卡与题数裁剪。归档时以本 change 的卡片与追问规格替换那一刀里相反的句子。

## Migration Plan

进行中的旧卡没有 `answerTurns` 时按单轮显示。不迁移已结束轮的目录。不改开场句，因此不要求考生重新安装以外的数据迁移。桌面验收仍要看一场「不会」留在原卡，和一场追深出现 `Qn.m`。

## Open Questions

无。两轮上限、五种结果和开卡映射已由规格定死。
