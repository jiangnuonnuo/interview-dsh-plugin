## Why

上一刀已经能开始一场八股陪练：新开考场对话、面试官问出第一问、面板给出本题要点。人设里写了「一次一问、答完再追」，宿主对话也会继续，但插件只 brief 了第一问，面板不再跟着走。现在要把「多轮」接到教练面板上，否则对照材料停在 Q1，开卷陪练不成立。

Desktop 实机又暴露第二层缺口：面试官经常在**同一条助手气泡**里先点评/揭晓上一问，再抛出下一问。现行看守把整段助手文本当题干，教练 JSON 跟着长段讲评走，面板就会停在「页分裂 / 磁盘 I/O」，而对话里当前待答问已经是「联合索引」。只比较「整段文本是否变化」不够；面板必须对齐**当前要求候选人作答的那一问**。

2026-09-17 在本机 DSH Desktop 0.2.17 sidecar `127.0.0.1:61915` 用 **MySQL 索引与优化 / 高级** 跑完 8 轮随意作答（含糊、跳过、跑题、短错、填料、否定、乱猜）。结论：**方案行得通**。8 轮里混合「讲评 + 待答问」是常态，不是例外；纯问句只出现在开场。抽出规则必须先跳过文末没有问号的议程句，再取最后一段连续问句——否则会把「问完后再说回头看两个维度」整段当题干。面板「刷新本题」仍要保留：第 5 轮对话已问页分裂时，要点曾短暂停在哈希。考场 JSON 在这 8 轮里既没出现，也不需要。

## What Changes

- 合法开始并出现第一问之后，候选人仍只在 **DSH 原输入框** 作答；插件 **MUST NOT** 再 `session.prompt` 催下一问，也 **MUST NOT** 自建聊天。
- 考场 Agent 进入空闲且**当前待答问**相对上一题变化时，会话 B 重新生成本题题干摘要与标准答要点，面板替换为新快照。
- 从最新面试官回合抽出待答问：优先可选标记 `【本题】`；否则先跳过文末不含 `？`/`?` 的议程/收束句，再取其后最后一段连续问句（含列表里的两问）；再否则整段。**MUST NOT** 在考场气泡里输出 JSON / `questionBrief`。教练会话 B 继续只返回面板 JSON。
- 进行中面板提供「刷新本题」：强制按当前待答问再 brief 一次，作为抽取或看守仍对不齐时的回退。刷新失败时面板展示可见错误，**MUST NOT** 清掉上一题快照，**MUST NOT** 空 catch。
- 五维评分区继续占位，本 change **不** 根据作答打分。
- 本 change 不做：提示/跳过、停止卸角、`study/` 落盘、项目深挖/混合模式。
- 查不到读最新题干或等待空闲的官方符号时，适配层标 `TODO` 并给出可见失败；**不得**用自建聊天或二次注入假用户气泡绕过。

选定方案（相对使用者提出的两条路）：

- **采用 A 的改写，而不是考场结构化气泡**：面板本来就靠会话 B 的 JSON；要抓的是「当前待答问」原文，由 Host 从自然语言回合抽出。考场里塞 JSON 会污染面试对话，也容易被模型包进散文。
- **同时采用 B 作回退**：面板「刷新本题」强制再 brief，不替代自动看守。
- **否决**「只做手动刷新」：每一问都要点按钮，自动路径仍然会跟错讲评。

上一刀 `interview-start-dual-session` **先不归档**。那份 spec 里「MUST NOT 处理用户作答后的追问」只约束那一刀；本 change 交付后，归档上一刀时须删掉或改写该句，避免主规格自相矛盾。不得把本刀任务回填进上一刀。

## Capabilities

### New Capabilities

- `interview-follow-up`: 第一问之后的多轮：宿主对话里面试官按人设追问；面板在**当前待答问**落地后刷新要点；混合「点评 + 新问」时对齐待答问而不是整段讲评；失败可见且可取消；允许手动强制刷新本题。

### Modified Capabilities

- （无。`interview-session` 尚未进入 `openspec/specs/`，本刀不改入口校验。）

## Impact

- `shared/`：增加「看守下一轮教练快照」的请求/响应与错误码（如 `follow_up_failed`）；看守请求可带可选 `force`；进行中快照仍不含前端可写分数。
- `backend/`：`data/` 记住本场 `sessionId`、上一道**待答问**原文与最新快照；`services/` 抽出待答问再 brief 教练；`infra/dsh/` 读最后一条人类用户之后的面试官可见文本，再抽出待答问并等待 Agent 空闲。Host `inject` 仍是 `agents` / `llm` / `agentDefaultModel`。
- `frontend/`：进行中面板在挂载期间通过 `ctx.remote` 循环看守；新快照替换题干与要点；提供「刷新本题」；关闭或卸载必须取消看守。`features/` 不 import Client SDK，无消息列表。
- `docs/architecture/ARCHITECTURE.md`：补上「后续轮次只看守、不再 prompt」、「读最后一条助手消息」和「brief 当前待答问而非整段点评」。
- 依赖：仅已随 Desktop 提供的 Host/Client SDK；无新密钥、无自建模型。
- 验收：实现者 MUST 亲自打开本机已在使用的 DSH Desktop，在 GUI 里走完「开始 → 第一问 → 宿主输入框作答 → 下一问 + 面板换要点」，并至少覆盖一轮「同一气泡先点评再提问」：面板题干摘要 MUST 对应文末待答问，MUST NOT 停在点评主题。`npm test`、代码审查、人设推理、上一刀第一问记录、三轮纯提问通过记录、Vite / 浏览器预览、`doc/entry-panel-mock.html`、新建 profile 或升级 Desktop **都不得**当作本刀通过。打不开 Desktop 则本刀未完成，不得勾选验收。
