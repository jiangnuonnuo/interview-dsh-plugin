## 1. 业务背景

秋招模拟面试已经有一套可用的面试官规范（`interviewer-role-prompt.md`）：一次一问、按梯度追问、卡住给提示、结束打分、沉淀标准答。今天它仍是「复制粘贴给任意 AI」的手工模板，没有产品形态。

候选人实际工作环境是 DeepSeek Harness（DSH，设计图中的 Xerina Harness）：写代码、对话、选模型，都在同一套 Web 里完成。他们不希望为了练八股再开一个独立聊天产品。

因此本产品的起点不是「再做一个聊天框」，而是：**在用户正在使用的那条 DSH 对话上，套上一场八股专项陪练，并在右侧给出教练式对照。**

提示词里有三种模式：项目深挖、八股专项、混合。第一期只做八股专项，用来验证「当前对话当考场 + 右侧当教练」这条工作方式是否成立。

---

## 2. 问题与目标

### 2.1 要解决的问题

- 练八股必须离开编码环境，去另一个对话里复制提示词。
- 面试官、标准答案、评分混在同一段聊天里，既不像面试，也不好回顾。
- 练完没有稳定资产，无法回到某次主题的对话、报告和标准答。

### 2.2 第一期目标

打通一条可演示的主链路：

1. 在 DSH 里点「面试」就能开始八股陪练。
2. 面试官在**当前这条对话**里提问和追问。
3. 右侧面板从一开始就给出本题标准答要点，并显示评分，保证用户能对着要点回答。
4. 结束后面试官角色立刻卸掉，对话变回普通助手。
5. 本场对话记录、评分报告、各题标准答写入当前工作区的 `study/` 目录。

### 2.3 成功标准（产品）

一次完整练习后，用户能感觉到：左边在被面，右边在对照；停下来之后还能继续用这条对话写代码；工作区里留下本场文件。不要求跑题处理、时长控制、选文件夹等旁路。

## 3. 产品定义

`interview-dsh` 是 DSH 上的**八股专项陪练插件**。

同一屏双角色：

| 位置 | 角色 | 用户感知 |
|---|---|---|
| DSH 现有对话 | 面试官 | 提问、追问、提示、跳过换题、结束语 |
| 右侧插件面板 | 教练 | 入口配置、本题要点、标准答、评分、简报 |

插件**不提供**独立聊天页、消息列表、输入框或气泡。说话只发生在 DSH 原对话里。

这不是闭卷考场，而是开卷陪练：标准答要点在题目出现时就可以看，目的是保证后续可回答性。聊天里的面试官仍然不把完整标准答贴进气泡。

---

## 4. 用户与场景

| 角色 | 说明 |
|---|---|
| 候选人（第一期唯一用户） | 在自己的 DSH 工作区里练八股，自测、对照、留档 |
| 不是 | HR、旁观教练、面试官后台 |

主场景只有一个：候选人打开 DSH → 点「面试」→ 选主题和难度 → 在当前对话里完成一场八股陪练 → 停止或被问完 → 回到普通助手，并在 `study/` 里看到本场文件。

---

## 5. 范围

### 5.1 第一期做

- 输入栏「面试」入口面板（与「AI 优化」同级，新会话首页可见）：主题（预设 + 自定义）、难度、开始。
- 占用**当前正在查看的 DSH 对话**作为面试现场。
- 同一套「这次对话配置的 AI」，两个互不混淆的会话：对话会话（面试官）与面板会话（教练）。
- 面试官动态出题和追问（八股梯度：是什么 → 为什么 → 场景 → 挖到边界）。
- 面板从一开始展示本题标准答要点和评分。
- 对话区动作：提示一下、跳过问题、停止面试。
- 结束（停止或问完）后立刻恢复普通助手。
- 默认落盘到当前打开工作区下的 `study/`。

### 5.2 第一期不做

- 独立聊天 UI。
- 时长、倒计时、到点自动结束。
- 开始时让用户选择文件夹。
- 跑题 / 面试中途当编程助手 / 拉回策略（进行中每条用户消息都当本题回答）。
- 标准答开场隐藏（不做闭卷）。
- 提示、跳过由面板生成内容（这两件事只由面试官在对话里做）。
- 项目深挖、混合模式、简历解析。
- 内置死题库作为出题主路径。
- 音视频、外部数据库、云端档案。

## 6. 主链路（验收路径）

以下是第一期唯一必须跑通的路径。旁路场景不设计、不验收。

```
点输入栏「面试」（新会话首页，「AI 优化」旁）
    -> 右侧打开入口：主题 / 难度 / 开始
    -> 点「开始模拟面试」
    -> 当前对话套上面试官（不读开始前历史）
    -> 同时建立面板会话（同一 AI 配置，输出不进对话）
    -> 对话出现第一问；面板立刻出现本题标准答要点与评分区
    -> 用户在 DSH 输入框作答 -> 面试官追问或换点
    -> 新题出现时，面板换成新题的要点与评分
    -> 可选：提示一下 / 跳过问题（均为面试官说话）
    -> 点「停止面试」，或面试官问完自行收尾
    -> 一句结束语 -> 立刻卸角色，对话变回普通助手
    -> 面板出简报
    -> 写入 <当前打开的工作区>/study/<本场目录>/
```

再开一场：仍占用当前这条对话，是新的一场；上一场内容视为场前历史，不喂给新面试官。

## 7. 功能需求

### 7.1 入口

- 从 DSH 输入栏打开「面试」（`conversation.input.right`，与本机「AI 优化」同槽），只展开右侧面板，不跳转、不新建聊天页、不更换当前对话。新会话首页没有 session header，不得把主入口放在顶栏 utilities。面板挂在官方右侧 tab（若桌面端提供）或 `shell.overlay` 右侧抽屉；不要求用户配快捷键。
- 用户可搜索或点选预设主题，也可自定义主题。
- 用户选择难度：初级 / 中级 / 高级。难度只影响面试官追问深浅，不是换一套死题。
- 主操作是「开始模拟面试」。
- 不要时长选择，不要开始前强制选目录。

预设主题的具体清单以实现时入口图为准，允许后续增删；自定义主题必须可用。

### 7.2 开始时的会话规则

开始之后，产品上有两条并行、禁止混淆的会话，但都使用**当前这条 DSH 对话已经配置好的 AI**（模型、参数、密钥来源），插件不得另配一套模型。

**会话 A：对话会话（面试官）**

- 唯一可见的说话表面。
- 从「开始」这一刻新建面试官上下文：不读本对话里开始之前的任何消息。
- 只产出面试官的提问、追问、提示、换题说明、结束语。
- 禁止看到面板的系统提示、评分过程、标准答生成过程。

**会话 B：面板会话（教练）**

- 用户看不见这条会话本身，只看见面板结果。
- 只产出题干要点、标准答要点、评分、深度记录、简报。
- 输出永远不进入对话气泡。
- 只使用「开始之后」的面试材料；同样不读场前历史。

允许的单向：对话里已经发生的问答，可以作为材料交给面板去生成标准答和评分。  
禁止的反向：面板内容回流给面试官。

### 7.3 对话中的面试官

- 开场说明本轮主题和难度，然后立刻问第一个问题；每次只问一个问题。
- 按八股专项规则，根据用户回答决定深挖、换方向或收束本题。
- 用户在 DSH 原输入框里回复；MVP 把进行中的每条用户消息都当作对本题的回答，不做跑题识别。
- 题目由模型按主题和本场面试对话动态生成，不靠预写题库驱动。

### 7.4 教练面板

面试进行中，右侧至少展示：

- 本场进行中状态与当前主题。
- 当前题干摘要。
- 本题标准答要点：**题目一出现就可以看**，不必等用户作答。
- 评分信息（八股五维：基础扎实度 / 原理理解 / 场景迁移 / 深度边界 / 表达清晰度）。评分可在用户作答后更新；标准答要点不得因此推迟到作答之后才出现。

面板不承担「提示一下」「跳过问题」的内容生成。设计图中这两个动作属于对话侧，不是教练会话的职责。

结束后面板展示本场简报（覆盖点、五维、主要短板），直到用户关闭或开始下一场。

### 7.5 提示、跳过、停止

| 动作 | 谁执行 | 用户看到什么 | 面板 |
|---|---|---|---|
| 提示一下 | 面试官（会话 A） | 对话里出现引导（方向 / 选项 / 例子），不把标准答全文贴进聊天 | 无关系：不生成、不展示提示 |
| 跳过问题 | 面试官（会话 A） | 对话里收束本题并问下一个点 | 只事后把本题深度记为未挖或部分 |
| 停止面试 | 结束整场 | 面试官说结束语后立刻恢复普通助手 | 出简报并触发落盘 |

「提示一下」「跳过问题」若做按钮，放在对话区（输入附近），不要做成评估面板功能。

### 7.6 结束与恢复普通助手

以下两种结束等价：

1. 用户点「停止面试」。
2. 面试官把该问的点问完，自行收尾。

结束时必须：

- 对话里有一句结束语。
- **立刻卸下面试官角色**，当前对话马上变回普通 DSH 助手（仍是原对话那套 AI 配置）。
- 之后的新消息不再当作本场面试回答。
- 不在对话里刷五维大表或标准答全文。
- 面板进入简报；本场文件写入 `study/`。

面试是套在这条对话上的一段模式：开始套上，结束摘掉。

### 7.7 落盘

- 开始不选文件夹。
- 根目录 = 用户当前打开的工作区下的 `study/`。
- 每一场一个子目录，避免覆盖。建议形态：

```
<当前打开的工作区>/study/
  <日期>-<主题>/
    conversation.md      本场对话记录
    report.md            评分报告
    answers/             各题标准答
      01-<题名>.md
```

- 三件套都必须有：对话记录、评分报告、各题标准答。
- 写入失败必须让用户在面板上看到失败，不能静默当成功。
- 文件名细节可在实现时定，不改变「`study/` + 一场一目录 + 三件套」的产品约定。

## 8. 面试官内容口径（产品层）

来源是 `interviewer-role-prompt.md` 的八股专项，第一期固定为：

- 模式：八股专项（不开项目深挖 / 混合）。
- 风格：对话里像真实面试官；对照和分数放在面板。
- 梯度：是什么 → 为什么 → 场景 → 深挖到边界。
- 提示：只出现在对话里，逐级降提示，默认不在聊天给完整答案。
- 评分维度：基础扎实度 / 原理理解 / 场景迁移 / 深度边界 / 表达清晰度（1–5，可 .5）。

入口难度与追问深浅的对应（产品意图，不是题库）：

| 难度 | 面试官 |
|---|---|
| 初级 | 定义清楚 + 常见场景，少换约束 |
| 中级 | 原理 / 取舍 + 场景迁移 |
| 高级 | 挖到边界，可换前提 / 换规模 |

设计图上的「技术深度 / 逻辑思维 / …」仅作视觉参考，需求口径以本节五维为准。
