## 1. 是什么

`interview-dsh` 是跑在 DeepSeek Harness（DSH）上的**八股专项陪练插件**。

候选人已经在 DSH 里写代码、对话、选模型。他们不希望为了练八股再开一个独立聊天产品，也不希望面试官、标准答案和评分挤在同一段气泡里。

因此产品形态是：

| 位置 | 角色 | 用户感知 |
|---|---|---|
| DSH 现有对话 | 面试官 | 提问、追问、提示、换题、结束 |
| 右侧插件面板 | 教练 | 开始一场练习、看要点、看对照、看简报 |

插件不提供独立聊天页。说话只发生在 DSH 原对话里。这是开卷陪练，不是闭卷考场。

内容口径参考 `interviewer-role-prompt.md` 里的八股专项。那份提示词还有项目深挖和混合模式；**当前产品方向只做八股专项**，用来验证「当前对话当考场 + 右侧当教练」这条工作方式。

## 2. 给谁用

| 角色 | 说明 |
|---|---|
| 候选人（当前唯一用户） | 在自己的 DSH 工作区里练八股：自测、对照、留档 |
| 不是 | HR、旁观教练、面试官后台 |

主场景：候选人打开 DSH → 开始一场八股陪练 → 在当前对话里作答 → 在右侧对照 → 结束后回到普通助手，并在工作区留下本场材料。

## 3. 当前方向

下面是方向，不是验收条款。范围、字段、按钮位置、落盘路径、评分何时出现，都由对应 OpenSpec change 决定。

- 练八股不必离开编码环境。
- 左边被面、右边对照；面试官角色只覆盖这一场，结束即摘掉。
- 面试官按主题动态出题，不靠内置死题库当主路径。
- 练习结果落到当前工作区，失败时用户能看见。
- 不做独立聊天产品，也不把本插件做成项目深挖或混合模式面试。

UI 稿（`doc/entrance.png`、`doc/layout.png`、`doc/entry-panel.png`）是视觉参考，不是需求锁。设计图里出现但当前 change 未写入的能力（时长、倒计时、其它评分维度等）不要自行补上。

## 4. 和 OpenSpec 的关系

1. 从方向里拆出可验证的 change，在 OpenSpec 里讨论行为、设计和任务。
2. 实现只对应当前 change 的 spec / design / tasks，并遵守架构文档。
3. 不要从已废弃的 bagua-mode 文档倒推产品。
4. 需要调整方向时，先改本节的方向描述，再开或改 OpenSpec change；不要把实现细节回写成本文的强制清单。
