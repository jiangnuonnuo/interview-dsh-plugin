## 1. 是什么

`interview-dsh` 是跑在 DeepSeek Harness（DSH）上的**八股专项陪练插件**。

候选人已经在 DSH 里写代码、对话、选模型。他们不希望为了练八股再开一个独立聊天产品，也不希望面试官、标准答案和评分挤在同一段气泡里。

因此产品形态是：

| 位置 | 角色 | 用户感知 |
|---|---|---|
| 本场考场对话（项目下新开的 DSH 会话） | 面试官 | 提问、追问、提示、换题、结束 |
| 右侧插件面板 | 教练 | 开始一场练习、看开卷要点、看对照与五维、左右切回已答卡 |

插件不提供独立聊天页。说话只发生在 DSH 原对话里，但**考场不是用户正在写代码的那条对话**：从某个项目页点开始后，插件在该项目分组下新开一场面试官会话。这是开卷陪练，不是闭卷考场。

内容口径参考 `interviewer-role-prompt.md` 里的八股专项。那份提示词还有项目深挖和混合模式；**当前产品方向只做八股专项**，用来验证「项目下的考场对话当面试官 + 右侧当教练」这条工作方式。

## 2. 给谁用

| 角色 | 说明 |
|---|---|
| 候选人（当前唯一用户） | 在自己的 DSH 工作区里练八股：自测、对照、留档 |
| 不是 | HR、旁观教练、面试官后台 |

主场景：候选人打开某个项目工作区 → 点输入栏「面试」→ 选主题与难度开始 → 在该项目下的新考场对话里作答 → 右侧按题看开卷要点、交卷后的对照与分数 → 点「结束本场」后面试官用固定收尾句结束本轮，工作区留下逐题卡片、一份问答汇总 md 与一份总结 md；同一条考场对话可再开一轮。不摘人设。问答与总结是工作区里的 md，给人拿到笔记库去用，面板不当阅读器或编辑器。教练面板的卡片形态见 3.1。

## 3. 当前方向

下面是方向，不是验收条款。范围、字段、按钮位置、落盘路径，都由主规格或对应 OpenSpec change 决定。

八股专项主链路：

- 练八股不必离开编码环境，也不必把面试官注入正在写代码的对话。
- 考场会话挂在用户点开始时所在的项目分组下，不得落到「未分组」当默认去处。
- 左边被面、右边对照：每题一张卡（含追问编号），题目一出现就有开卷要点；候选人作答后立刻给出本题对照与八股五维，不必等整场结束。
- 简报就是可切回的逐题评分卡，不是场末长文。
- 面试官按主题动态出题，不靠内置死题库当主路径。
- 本场材料落到当前工作区、与这场考场会话绑定；失败时用户能看见。旧的笔记式目录不再作为新场落点。
- 点「结束本场」后面试官用固定收尾句结束本轮；本轮问答汇总与总结写入工作区，给人当 md 导入笔记库；同一条考场对话可再开一轮。不摘人设。
- 不做独立聊天产品，也不把本插件做成项目深挖或混合模式面试。

### 3.1 教练面板的卡片化方向

右侧面板必须保持为 DSH 内的教练面板，不能扩展成独立面试系统。DSH 对话是唯一的问答表面，卡片只负责查看题目、开卷要点、作答状态、对照与评分。

面板采用轻量的平面折叠卡片，不使用复杂 3D 轮播：

- 卡片流态一次突出一张当前卡，上一题和下一题只露出局部。
- 向左滑动切到下一题，向右滑动切到上一题；上一题、下一题按钮继续保留作为辅助操作。
- 点击当前卡进入同一面板内的完整详情态；详情态仍可左右滑动，直接切换到相邻题目的完整内容。
- 详情态通过「返回卡片流」回到卡片流，不新开页面、不遮挡 DSH 对话。
- 面试官提出新题后，旧卡保持可见，面板显示「正在生成本题」；要点生成完成后追加新卡并自动定位到最新卡。
- 已答卡片必须保留原题、作答、对照与五维评分，可通过滑动切回查看。

## 4. 和 OpenSpec 的关系

1. 从方向里拆出可验证的 change，在 OpenSpec 里讨论行为、设计和任务。
2. 实现只对应当前 change 的 spec / design / tasks，并遵守架构文档；无进行中 change 时以 `openspec/specs/` 为准。
3. 不要从已废弃的 bagua-mode 文档倒推产品。
4. 需要调整方向时，先改本节的方向描述，再开或改 OpenSpec change；不要把实现细节回写成本文的强制清单。
